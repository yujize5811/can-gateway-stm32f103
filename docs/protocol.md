# CAN-GW 协议说明（v1）

## 1. 物理层

| 项目 | 取值 |
|---|---|
| 速率 | 500 kbps |
| 位定时 | BRP=8，Sync=1 tq，BS1=6 tq，BS2=2 tq（36 MHz / (8×9) = 500 kHz） |
| 采样点 | (1+6)/9 = 77.8% |
| 终端电阻 | 总线两端各 120 Ω |

## 2. 帧 ID 分配（11 位标准帧）

| ID 范围 | 名称 | 方向 | 周期 / 说明 |
|---|---|---|---|
| 0x100 + node | HEARTBEAT | 节点 → 网关 | 1 Hz，负载含版本号与错误计数 |
| 0x200 + node | SAMPLE | 节点 → 网关 | 20 ms，8 字节定长 |
| 0x300 + node | CMD | 网关 → 节点 | 命令字 + 参数 |
| 0x400 + node | XFER | 双向 | 多帧传输（FF / CF） |
| 0x500 + node | ACK | 双向 | 确认 / NACK 请求重发 |

`node` 取值 0x01、0x02。

## 3. 单帧格式（HEARTBEAT / SAMPLE）

| 字节 | 内容 |
|---|---|
| 0 | [7:4] 类型，[3:0] 序号低 4 位 |
| 1–6 | 业务数据（采样值、状态位） |
| 7 | CRC8（多项式 0x07，初值 0x00，覆盖第 0–6 字节） |

## 4. 多帧传输（XFER）

```
FF（首帧）: [0x1F][总长H][总长L][SN=0][D0][D1][D2][CRC8]
CF（续帧）: [0x2C][SN  ][D0][D1][D2][D3][D4][CRC8]
```

- 每帧有效数据：FF 3 字节、CF 5 字节
- SN 从 0 递增，4 位循环（0–15）
- 接收端 100 ms 内未收到下一帧 CF → 回 NACK（携带期望的 SN）
- 整包收完 → CRC32 校验 → 通过回 ACK，失败回 NACK（整包重传）

## 5. 重传与超时

| 参数 | 值 | 说明 |
|---|---|---|
| ACK 超时 | 50 ms | 超时重发当前帧 |
| 最大重试 | 3 次 | 超过上报错误计数 |
| 对端离线判定 | 1 s 无心跳 | 网关侧标记离线 |
| 离线恢复判定 | 连续 2 帧心跳 | 自动重新上线 |

## 6. Bus-Off 恢复流程

```
1. 检测 CAN_ESR.BOFF 或 SCE 中断
2. 记录当前时刻 T0、进入故障计数
3. 请求进入初始化模式（CAN_MCR.INRQ = 1）
4. 重新配置过滤器
5. 退出初始化模式（INRQ = 0）
6. 记录 T1，统计恢复耗时
7. 恢复业务收发
```

## 7. 版本演进

| 版本 | 内容 | 吞吐 |
|---|---|---|
| v1.0 | 停等协议（发一帧等一个 ACK） | ~20 帧/s |
| v2.0 | 滑动窗口（窗口 4） | ~100 帧/s |
